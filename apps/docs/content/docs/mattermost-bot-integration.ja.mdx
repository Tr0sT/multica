Multica は、自社の Mattermost サーバーで作成したボットアカウントに接続します。1 つのボットが 1 つの Multica エージェントに対応します。独自の Mattermost アイデンティティが必要なエージェントごとに、別々のボットを作成してください。

Mattermost 対応は[コミュニティメンテナンス](/community-maintained)です。すべてのリリースに含まれますが、公式サポート SLA はありません。問題は [GitHub issues](https://github.com/multica-ai/multica/issues) に報告してください。

リンクを開くだけでは連携されません。Mattermost のユーザー名、サーバー、ワークスペース、Multica アカウントを確認してから、**アカウントを連携**を選択してください。他人のアカウント用リンクは承認しないでください。サーバーやボットを変更すると以前の連携とリンクは無効になりますが、Multica の履歴は保持されます。

## 事前準備

- ボットの接続は Multica ワークスペースのオーナーまたは管理者が行います。
- Multica API サーバーから Mattermost サーバーへ 許可された HTTPS URL で到達できる必要があります。Mattermost はセルフホストのため、多くの場合は公開アドレスではなく内部アドレスです。
- Mattermost 側でボットアカウントが有効になっている必要があります（**システムコンソール → インテグレーション → ボットアカウント**）。
- ボットのアクセストークンが必要です。パスワードと同じ扱いにしてください。

## 1. ボットアカウントを作成する

1. Mattermost で**システムコンソール → インテグレーション → ボットアカウント**を開き、ボットアカウントの作成が有効か確認します。
2. チームのメインメニューから**インテグレーション → ボットアカウント**を開き、**ボットアカウントを追加**をクリックします。
3. ユーザー名（メンバーが `@` メンションする名前）、表示名、アイコンを設定します。
4. **ボットアカウントを作成**をクリックし、表示されたトークンをコピーします。Mattermost はこれを一度しか表示しません。
5. ボットを動作させたいチャンネルに追加します。ボットは自分が参加しているチャンネルのメッセージしか受け取れません。

<Callout type="warning">
トークンを課題・チャットメッセージ・ログ・ソースリポジトリに貼り付けないでください。漏洩した場合は**インテグレーション → ボットアカウント**で失効させ、新しいトークンで再接続します。
</Callout>

<Callout type="info">
個人アクセストークンではなく**ボットアカウント**を使ってください。Multica は個人トークンを拒否します。自分の投稿が受信メッセージとして戻り、ボットが自分自身に応答してしまうためです。
</Callout>

## 2. エージェントに接続する

1. Multica で**エージェント**を開き、対象のエージェントを選択して**インテグレーション**を開きます。
2. **Mattermost に接続**をクリックします。
3. Mattermost のサーバー URL（例：`https://mattermost.example.com`）とボットアクセストークンを貼り付けます。
4. **このボットを利用できるユーザー**を選択します。
5. **エージェントに送信する履歴**を選択します。**チャット履歴**の場合は期間も選び、**接続**をクリックします。

Multica はサーバーに問い合わせてトークンを検証し、そのアカウントがボットであることを確認し、トークンを暗号化して保存し、監視付きの WebSocket 接続を 1 本開きます。すでに別のエージェントやワークスペースに接続済みのボットは、先にそちらで切断してください。

同じワークスペースに、同一または別のサーバーの複数のボットを接続できます。トークン、接続、コンテキスト設定、会話のルーティングはエージェントごとに独立しています。1 つの Mattermost ボットは 1 つのエージェントにのみ接続でき、各エージェントが接続できる Mattermost ボットも 1 つです。

### ボットを利用できるユーザー

- **アカウント連携済みの Multica ワークスペースメンバー**（デフォルト）：アカウント連携、現在のワークスペースのメンバー資格、エージェントの実行権限が必要です。
- **指定した Mattermost アカウント**を選ぶと、最大 100 件の `@ユーザー名` をカンマまたは改行で指定できます。追加するアカウントは接続先で検証し、アカウント ID で保存します。名前の変更で他のユーザーに権限が移ることはありません。Multica に連携済みでも、リストにないアカウントは利用できません。空のリストは全員を拒否します。Multica アカウントは不要で、リクエストはボットを接続したユーザーの権限、ツール、接続済みアプリを使用します。削除したアカウントは次のリクエストから拒否されます。
- **すべての Mattermost ユーザー**：Multica アカウントや連携なしで、DM やボット宛のチャンネルメッセージから利用できます。リクエストはボットを接続したユーザーに代わって実行されます。そのユーザーはワークスペースのメンバーであり、エージェントの実行権限を持つ必要があります。利用者はエージェントのツールと接続済みアプリを使用でき、作成された Multica チャットはボットを接続したユーザーが所有します。Multica アカウントやメンバー資格は作成されません。

返信は呼び出し元の DM またはチャンネルのスレッドに届きます。各 DM は独立しています。アクセスモードの変更は再接続せずに新しいリクエストへ適用され、モードごとに別の Multica 会話履歴を保持します。オーナーと管理者は接続済みボットの**編集**から変更できます。

**指定した Mattermost アカウント**モードでは、**リスト外のアカウントへの返信**をテキストまたはパソコンからアップロードした画像セットからランダムに選ぶ 1 枚に設定できます。画像は個別に追加・削除できます。返信ごとに独立して選ぶため、同じ画像が続く場合もあります。既存の単一画像設定は 1 枚のセットとして維持します。画像は PNG、JPEG、GIF、WebP、1 枚につき最大 5 MiB、テキストは最大 4000 文字です。空欄のテキストは標準のアクセス拒否メッセージになります。Mattermost に直接送信し、チャットやエージェントの実行を作成しないため、エージェントのトークンを消費しません。画像にキャプションは付きません。ボット宛でないチャンネル投稿や重複配信には再返信しません。画像を読み込めない場合やアップロードが拒否された場合は、標準の拒否メッセージを送信します。

### コンテキストを選ぶ

- **現在のメッセージのみ**（既定）：スレッドの先頭を含め、追加の Mattermost 履歴をエージェントに送信しません。
- **スレッド全体**：リクエストを含むスレッドを、そのメッセージまで取得します。トップレベルの投稿には先行するスレッド履歴はありません。
- **チャット履歴**：現在のチャンネルまたは DM の、リクエスト前 **1 時間、6 時間、24 時間、3 日、7 日、30 日、60 日、90 日、1 年（365 日）**の投稿と返信を取得します。**無制限**では期間を制限しませんが、以下のメッセージ数・サイズ・読み取り上限は引き続き適用されます。

要約用ボットでは**スレッド全体**を選び、議論の中で `@summary 決定事項、作業、担当者、未解決の質問をまとめて` とメンションします。チャンネル内の複数の議論をまとめる場合は**チャット履歴**を選びます。メッセージ内の URL をたどって別のチャンネルを読むことはありません。

取得した履歴には他の参加者の発言も含まれ、リクエストとともに Multica に保存され、エージェントのモデルに送信されます。既存の Multica 会話履歴とは別の設定です。`/new` や `/clear` で会話のコンテキストをリセットしても、次のリクエストで指定の Mattermost 履歴を再取得できます。変更するには、エージェントのインテグレーション画面または**設定 → メッセージング → Mattermost** で、接続済みボットの横にある**編集**を選んで保存します。アクセストークンは不要です。変更は通常 30 秒以内に自動で適用されます。

履歴は本文、投稿者、日時、投稿リンクのみです。1 回のリクエストにつき最大 1,000 件、シリアライズ後 128 KiB、1 投稿 4,000 文字で、ページ数と取得時間にも上限があります。省略時は部分履歴として明示し、エージェントにもその説明を求めます。取得失敗は利用不可として示します。ファイルや画像は取得しません。履歴が増えるとモデルのコンテキスト使用量も増えます。

## 初回利用とアカウント連携

以下のアカウント連携手順は、**アカウント連携済みの Multica ワークスペースメンバー**モードにのみ適用されます。

メンバーが初めてボットにメッセージを送ると、ボットは 1 回限りの Multica アカウント連携リンクを送ります。リンクを開いて同じ Multica ワークスペースにサインインし、表示されたアカウントを確認して連携を承認してから、Mattermost に戻ってもう一度メッセージを送ってください。リンクは 15 分で失効します。再度ボットにメッセージを送れば新しいリンクが届きます。

チャンネルでは、ボットがこのリンクを公開の場に投稿することはありません。まず DM を開くよう促します。

ボットを利用できるのは現在のワークスペースメンバーだけで、メンバーシップはメッセージごとに再確認されます。

## ボットを使う

### ダイレクトメッセージ

ボットとの DM を開いてテキストを送ります。`@` メンションは不要です。

### チャンネルとグループメッセージ

ボットをチャンネルに追加し、`@` メンションします。受理されたメッセージはそのスレッドの Multica 会話を継続します。ボット宛でないチャンネル上の雑談は収集されません。

追加のテキストなしで `@multica` だけを送っても、設定済みの指示と選択したコンテキストでエージェントが実行されます。

スレッドのルート投稿をボット自身が書いている場合は、メンションなしの返信もボットに届きます。ボットが始めた会話は名前を繰り返さずに続けられます。人が立てたスレッドでは、毎回メンションしてください。

各スレッドがそれぞれ独立した Multica チャットです。1 つのチャンネル内の 2 つのメンションスレッドは 2 つの独立した会話になり、DM は 1 本の連続した会話になります。

### コマンド

例では `@multica` を使います。実際のボットのユーザー名に置き換えてください。DM でも先頭にメンションを付け、Mattermost のスラッシュコマンドとして実行されないようにしてください。

- `@multica /issue <タイトル>` は Multica の課題を作成します。続く行は任意の説明になります。タイトルなしの `@multica /issue` は使い方を返します。
- `@multica /new` は空の Multica チャットを新規作成し、そのスレッドの以降のメッセージをそこへ振り分けます。`@multica /new <メッセージ>` はそのメッセージを最初のターンにします。
- `@multica /clear` は現在の Multica チャットを保ったまま、次の空でないメッセージからエージェントに見えるコンテキストを新しくします。

<Callout type="info">
これらは通常のメッセージ本文として入力する Multica のメッセージコマンドです。Mattermost のスラッシュコマンドではないため、システムコンソールへの登録は不要です。
</Callout>

### 返信と対応コンテンツ

ボットはリクエストが来たスレッドに返信し、エージェントの Markdown をそのままレンダリングし、サーバーの最大投稿サイズに収まるよう長い返信を分割します。返信はストリーミングではなく、エージェントの完了後に一度に投稿されます。

ボットはエージェントが生成した画像やファイルを送信できます。エージェントが `multica attachment upload <local-path>` を実行すると、返信テキストの後に各添付ファイルが同じスレッドの別の投稿として届きます。添付ファイルのみの返信にも対応します。Multica のオブジェクトストレージと、Mattermost でのボットの `upload_file` 権限が必要です。ファイルごとの上限は 100 MiB ですが、Mattermost サーバーの上限がそれより低い場合はそちらが適用されます。ファイルが利用できない場合やアップロードが恒久的に拒否された場合は、ボットが通知を投稿して残りのファイルの送信を続けます。

受信メッセージは引き続きテキストのみに対応します。テキストと添付ファイルを含む投稿はテキストとして扱われます。ファイル・画像などテキストを含まない投稿には、DM の場合とボットを明示的に宛先にした場合に未対応である旨を返します。ボット宛でないチャンネル上のメディアには何も返しません。

入力中インジケーターはありません。Mattermost は WebSocket 経由でのみそれを公開しており、処理中のメッセージに対して Multica から呼べるサーバー側の同等手段がないためです。

### 配信の復旧

返信と送信済みの部分はデータベースに記録され、再起動後も処理が再開されます。明確な一時的拒否は再試行されます。POST の応答を失った場合は、重複送信せずボットの送信マーカーを検索します。結果を確認できない場合は照合待ちとしてログに残るため、手動で再送する前に Mattermost と Multica の返信を確認してください。照合の上限は 4000 件です。WebSocket 切断中の受信メッセージは再取得しません。

## 接続を管理する

**設定 → メッセージング → Mattermost** で、接続済みボットと各ボットが属するサーバーを確認できます。オーナーと管理者は切断できます。切断すると接続が閉じて送信も止まりますが、Multica の会話と監査記録は保持されます。

## セルフホスト設定

API サーバーを起動する前に、安定した 32 バイトの暗号化キーを設定します。

運用担当者は `MULTICA_MATTERMOST_ALLOWED_SERVERS` に、許可する HTTPS ベース URL をカンマ区切りで設定してください。サブパスがある場合は含めます。HTTP、認証情報付き URL、クエリ、フラグメント、未許可の接続先は拒否されます。URL を削除すると、既存の接続も次回の接続・送信時に拒否されます。

```dotenv
MULTICA_MATTERMOST_SECRET_KEY=<base64 エンコードされた 32 バイトのキー>
MULTICA_MATTERMOST_ALLOWED_SERVERS=https://mattermost.example.com
```

`openssl rand -base64 32` で生成できます。長期的に保管してください。紛失やローテーションを行うと保存済みのボットトークンが復号できなくなり、各ボットの再接続が必要になります。

各インストールは運用担当者が許可したサーバー URL を使用します。複数のサーバーを許可リストに設定できます。

連携リンクは `MULTICA_APP_URL`（未設定時は `FRONTEND_ORIGIN`）を使います。生成されるアドレスはメンバーから到達可能である必要があります。

<Callout type="warning">
Multica は Mattermost サーバーとの通信で HTTP リダイレクトを一切追跡しません。設定ミスによるリダイレクトでボットトークンが別のホストに送られることはありません。デプロイでリダイレクト（HTTP から HTTPS など）が発生する場合は、ブラウザーで実際に使う最終 URL を入力してください。
</Callout>

## トラブルシューティング

- **ボットを検証できない**：まずサーバー URL と API サーバーのネットワーク／プロキシ設定を確認します。トークンの再発行が必要なのは Mattermost 自身が拒否した場合だけで、エラーメッセージが両者を区別します。
- **「このトークンはユーザーアカウントのものです」**：個人アクセストークンを貼り付けています。ボットアカウントを作成し、そのトークンを使ってください。
- **チャンネルで返信がない**：ボットがそのチャンネルのメンバーであること、メッセージが `@` メンションしているか、ボットが始めたスレッドへの返信であることを確認します。
- **`@channel` でボットが動かない**：意図した挙動です。ボットは自分の名前にのみ反応するため、ブロードキャストのメンションでチャンネル中のボットが一斉に反応することはありません。
- **連携リンクの期限切れ**：ボットにもう一度 DM を送り、最新のリンクを使ってください。
- **ボットが実行されない**：エージェントがアーカイブされていないか、[ランタイム](/daemon-runtimes)がオンラインかを確認します。
