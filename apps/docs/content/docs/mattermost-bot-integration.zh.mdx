Multica 连接的是你在自有 Mattermost 服务器中创建的机器人账号。一个机器人对应一个 Multica 智能体。需要独立 Mattermost 身份的每个智能体，都要单独创建机器人。

Mattermost 支持属于[社区维护](/community-maintained)：它随每个版本发布，但不提供官方支持 SLA。问题请提交到 [GitHub issues](https://github.com/multica-ai/multica/issues)。

打开链接只会预览账号。请核实 Mattermost 用户名、服务器、工作区和当前 Multica 账号，再选择**关联账号**。不要确认别人发来的、属于其他账号的链接。更换服务器或机器人会清除原有的用户和会话路由并使旧链接失效，但 Multica 聊天记录会保留。

## 开始之前

- 需要由 Multica 工作区所有者或管理员来连接机器人。
- Multica API 服务器必须能通过获批的 HTTPS 地址 访问你的 Mattermost 服务器。由于 Mattermost 是自部署的，这通常是内网地址而非公网地址。
- 需要在 Mattermost 中启用机器人账号（**系统控制台 → 集成 → 机器人账号**）。
- 需要机器人的访问令牌，请像对待密码一样保管它。

## 1. 创建机器人账号

1. 在 Mattermost 中打开**系统控制台 → 集成 → 机器人账号**，确认允许创建机器人账号。
2. 从团队主菜单打开**集成 → 机器人账号**，点击**添加机器人账号**。
3. 填写用户名（成员将用它来 @ 提及）、显示名称和头像。
4. 点击**创建机器人账号**并复制显示的令牌。Mattermost 只会显示一次。
5. 把机器人加入它需要工作的频道。机器人只能收到自己所在频道的消息。

<Callout type="warning">
切勿把令牌粘贴到任务、聊天消息、日志或代码仓库中。一旦泄露，请在**集成 → 机器人账号**中吊销，并用新令牌重新连接。
</Callout>

<Callout type="info">
请使用**机器人账号**，不要使用个人访问令牌。Multica 会拒绝个人令牌：那样机器人自己发出的消息会作为入站消息回流，导致自问自答。
</Callout>

## 2. 连接到智能体

1. 在 Multica 中打开**智能体**，选择一个智能体，进入**集成**。
2. 点击**连接 Mattermost**。
3. 粘贴 Mattermost 服务器地址（例如 `https://mattermost.example.com`）和机器人访问令牌。
4. 选择**谁可以使用此机器人**。
5. 选择**发送给智能体的历史记录**；如果选择**聊天历史**，还需选择时间范围。点击**连接**。

Multica 会调用你的服务器校验令牌、确认该账号是机器人、加密保存令牌，并建立一条受监管的 WebSocket 连接。若该机器人已连接到其他智能体或工作区，需先在那里断开。

同一个工作区可以连接同一台或不同服务器上的多个机器人。每个智能体独立保存令牌、连接、上下文设置和对话路由。一个 Mattermost 机器人只能属于一个智能体，每个智能体也只能连接一个 Mattermost 机器人。

### 谁可以使用机器人

- **已绑定账号的 Multica 工作区成员**（默认）：需要绑定账号、属于当前工作区，并拥有运行智能体的权限。
- **指定的 Mattermost 账号**：输入最多 100 个 `@用户名`，以逗号或换行分隔。新增账号会在已连接的 Mattermost 服务器上验证，并按账号 ID 保存；改名不会将权限转移给其他人。只有列表中的账号可以使用机器人，其他已绑定 Multica 的账号也不例外。空列表会阻止所有人访问。与“任何 Mattermost 用户”模式一样，无需 Multica 账号，请求使用安装者的权限、工具和已连接应用。移除账号后，其下一次请求会被拒绝。
- **任何 Mattermost 用户**：无需 Multica 账号或账号绑定，即可通过私聊或频道中指向机器人的消息发起请求。请求以机器人安装者的身份运行；安装者必须仍是工作区成员，且拥有运行智能体的权限。这些用户可以使用智能体的工具和已连接应用；生成的 Multica 聊天归安装者所有。不会创建 Multica 账号或成员关系。

回复保留在调用机器人的位置：私聊或原频道话题串。不同私聊相互独立。访问模式更改对新请求立即生效，无需重新连接；每种模式保留独立的 Multica 对话历史。工作区所有者和管理员可点击已连接机器人旁的**编辑**修改设置。

### 选择上下文

- **仅当前消息**（默认）：不向智能体发送额外的 Mattermost 历史，包括讨论串的首条消息。
- **整个讨论串**：读取请求所在的讨论串，截至该请求。顶层消息没有更早的讨论串消息。
- **聊天历史**：读取当前频道或私聊在请求前 **1 小时、6 小时、24 小时、3 天、7 天、30 天、60 天、90 天或 1 年（365 天）**内的消息和回复。**不限**表示不限制日期；下述消息数量、大小和读取预算限制仍然适用。

总结机器人可以选择**整个讨论串**，然后在讨论中发送 `@summary 总结决策、待办事项、负责人和待确认的问题`。跨讨论总结请选择**聊天历史**。适配器不会根据消息中的链接读取其他频道。

选中的历史（包括其他参与者的消息）会随请求保存到 Multica，并发送给智能体使用的模型。现有 Multica 对话历史独立保留；`/new` 和 `/clear` 重置对话上下文后，下次请求仍可重新读取所选 Mattermost 历史。要修改设置，请在智能体的集成页或**设置 → 消息 → Mattermost** 中，点击已连接机器人旁的**编辑**并保存。无需再次输入访问令牌。更改会自动生效，通常不超过 30 秒。

历史仅包含文本、作者、时间和消息链接。每次请求最多读取 1,000 条消息，序列化内容不超过 128 KiB，每条消息最多 4,000 个字符，并限制分页次数和读取时间。超限时会标记为部分历史并要求智能体说明；读取失败时会标记为不可用。不下载文件或图片。历史越多，模型上下文用量越大。

## 首次使用与账号绑定

以下账号绑定流程仅适用于**已绑定账号的 Multica 工作区成员**模式。

成员第一次给机器人发消息时，机器人会发送一个一次性的 Multica 账号绑定链接。打开链接、登录同一个 Multica 工作区，核实并确认显示的账号关联，然后回到 Mattermost 重新发送消息。链接 15 分钟后过期；重新给机器人发消息即可获取新链接。

在频道中，机器人绝不会公开发布该链接，而是提示发送者先开启私聊。

只有当前工作区成员可以使用机器人，并且每条消息都会重新校验成员身份。

## 使用机器人

### 私聊

与机器人开启私聊并直接发送文本，无需 @ 提及。

### 频道与群组消息

把机器人加入频道后 @ 提及它。被接受的消息会延续该话题串对应的 Multica 会话；未指向机器人的频道闲聊不会被采集。

只发送 `@multica` 也会调用智能体，并使用已配置的指令和所选上下文。

如果话题串的根消息本身由机器人发出，那么串内不带 @ 的回复同样会送达机器人——机器人发起的对话可以直接继续，无需反复提及它。若话题串由真人发起，则每次都需要 @ 提及。

每个话题串都是独立的 Multica 会话。同一频道中的两个 @ 提及话题串是两段互不干扰的对话；私聊则是一段连续对话。

### 命令

示例使用 `@multica`，请替换为实际的机器人用户名。私聊中也要先加上提及，避免 Mattermost 将消息当作原生斜杠命令执行。

- `@multica /issue <标题>` 创建 Multica 任务，后续行作为可选描述。只输入 `@multica /issue` 会返回用法提示。
- `@multica /new` 创建一个新的空 Multica Chat，并把该话题串后续消息路由进去。`@multica /new <消息>` 会把该消息作为首轮内容。
- `@multica /clear` 保留当前 Multica Chat，并为下一条非空消息应用全新的智能体可见上下文。

<Callout type="info">
这些是 Multica 的消息命令，按普通消息文本输入即可。它们不是 Mattermost 斜杠命令，无需在系统控制台注册。
</Callout>

### 回复与支持的内容

机器人会在请求所在的话题串中回复，原生渲染智能体输出的 Markdown，并按服务器的最大消息长度自动分段。回复在智能体完成后一次性发出，不是流式的。

机器人可以发送智能体生成的图片和文件。智能体使用 `multica attachment upload <local-path>` 上传后，每个附件会在回复文本之后，作为同一话题串中的单独消息发出，也支持只有附件的回复。这需要 Multica 配置对象存储，且机器人在 Mattermost 中拥有 `upload_file` 权限。每个文件上限为 100 MiB；如果 Mattermost 服务器限制更低，则以该限制为准。文件不可用或上传被永久拒绝时，机器人会发送提示并继续发送其他文件。

接收消息仍仅支持文本。同时包含文本和附件的消息按文本处理；只有文件、图片或其他非文本内容的消息，会在私聊中以及明确指向机器人时收到明确的不支持提示，未指向机器人的频道媒体消息则保持静默。

没有"正在输入"提示：Mattermost 仅通过 WebSocket 暴露该能力，对于正在处理中的消息，Multica 没有可调用的服务端等价接口。

### 发送恢复

回复及已发送的分段会记录在数据库中，重启后可继续处理，并重试明确的暂时性拒绝。如果 POST 响应丢失，会查找机器人的发送标记，避免盲目重复发送。无法确认结果时保留待核对状态并记录日志；手动重发前请检查 Mattermost 话题串和 Multica 中保存的回复。核对最多扫描 4000 条消息。此适配器不会补取 WebSocket 断线期间的入站消息。

## 管理连接

打开**设置 → 消息渠道 → Mattermost** 查看已连接的机器人及其所属服务器。所有者和管理员可以断开连接。断开会关闭连接并停止外发回复，但会保留 Multica 中的会话与审计记录。

## 自部署配置

启动 API 服务器前，设置一个稳定的 32 字节加密密钥：

运维人员必须在 `MULTICA_MATTERMOST_ALLOWED_SERVERS` 中配置允许访问的完整 HTTPS 基础地址，以逗号分隔，并包含部署子路径。HTTP、包含凭据、查询参数或片段的 URL，以及未批准的地址都会在连接前被拒绝。移除地址后，已有集成的后续连接和发送也会被拒绝。

```dotenv
MULTICA_MATTERMOST_SECRET_KEY=<base64 编码的 32 字节密钥>
MULTICA_MATTERMOST_ALLOWED_SERVERS=https://mattermost.example.com
```

可用 `openssl rand -base64 32` 生成。请长期保存：一旦丢失或轮换，已存储的机器人令牌将无法解密，需要重新连接每个机器人。

每个集成都使用运维人员批准的服务器地址；允许列表可以包含多个服务器。

绑定链接使用 `MULTICA_APP_URL`，回退到 `FRONTEND_ORIGIN`。生成的地址必须能被成员访问。

<Callout type="warning">
Multica 访问你的 Mattermost 服务器时从不跟随 HTTP 重定向，因此错误配置的重定向不会把机器人令牌发往其他主机。如果你的部署存在重定向（例如 HTTP 跳转 HTTPS），请填写最终地址——也就是你在浏览器中实际使用的那个。
</Callout>

## 故障排查

- **无法验证机器人**：先检查服务器地址以及 API 服务器的网络或代理设置。只有当 Mattermost 明确拒绝当前令牌时才需要重新生成——错误提示会区分这两种情况。
- **提示"该令牌属于用户账号"**：你粘贴的是个人访问令牌。请创建机器人账号并使用它的令牌。
- **频道中没有回复**：确认机器人在该频道内，且消息 @ 提及了它，或是在机器人发起的话题串中回复。
- **`@channel` 不会触发机器人**：这是刻意设计。机器人只响应自己的名字，广播式提及不会惊动频道里的每个机器人。
- **绑定链接过期**：重新给机器人发一条私聊消息，使用最新的链接。
- **机器人不执行**：检查智能体是否已归档，以及其[运行时](/daemon-runtimes)是否在线。
