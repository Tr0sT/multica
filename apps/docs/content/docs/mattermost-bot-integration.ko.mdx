Multica는 사용자가 자체 Mattermost 서버에서 만든 봇 계정에 연결합니다. 봇 하나가 Multica 에이전트 하나에 대응합니다. 고유한 Mattermost 신원이 필요한 에이전트마다 별도의 봇을 만드세요.

Mattermost 지원은 [커뮤니티 유지보수](/community-maintained) 영역입니다. 모든 릴리스에 포함되지만 공식 지원 SLA는 없습니다. 문제는 [GitHub issues](https://github.com/multica-ai/multica/issues)에 신고해 주세요.

링크를 여는 것만으로 계정이 연결되지는 않습니다. Mattermost 사용자 이름, 서버, 워크스페이스와 Multica 계정을 확인한 후 **계정 연결**을 선택하세요. 다른 사람의 계정에 대한 링크를 승인하지 마세요. 서버나 봇을 교체하면 이전 연결과 링크는 무효화되지만 Multica 대화 기록은 유지됩니다.

## 채팅 참여자와 열람 권한

채팅 목록과 헤더에는 다이렉트 메시지 상대의 Mattermost 사용자 이름이나 그룹 스레드의 채널 이름이 표시됩니다. 이름은 수신 메시지와 함께 저장됩니다. 이름이 없는 기존 채팅은 다음 메시지를 받으면 업데이트됩니다.

워크스페이스 소유자와 관리자는 「채팅 소유자」 필터로 내 채팅, 모든 멤버의 채팅 또는 특정 멤버의 채팅을 볼 수 있습니다. 다른 관리자의 채팅도 열람할 수 있습니다. 다른 사람의 채팅은 읽기 전용이며 읽음으로 표시되지 않습니다. 메시지 전송, 이름 변경, 고정, 보관, 삭제는 소유자만 할 수 있습니다. 일반 멤버는 자신의 채팅만 볼 수 있습니다.

필터는 Multica 채팅 소유자를 기준으로 합니다. Multica 계정을 연결하지 않은 Mattermost 사용자의 채팅은 봇 설치자에게 속하며, 실제 대화 상대는 Mattermost 사용자 이름으로 확인할 수 있습니다.

## 시작하기 전에

- 봇 연결은 Multica 워크스페이스 소유자 또는 관리자가 해야 합니다.
- Multica API 서버가 승인된 HTTPS URL로 Mattermost 서버에 접근할 수 있어야 합니다. Mattermost는 셀프 호스팅이므로 공개 주소가 아닌 내부 주소인 경우가 많습니다.
- Mattermost에서 봇 계정이 활성화되어 있어야 합니다(**시스템 콘솔 → 통합 → 봇 계정**).
- 봇의 액세스 토큰이 필요합니다. 비밀번호처럼 다루세요.

## 1. 봇 계정 만들기

1. Mattermost에서 **시스템 콘솔 → 통합 → 봇 계정**을 열고 봇 계정 생성이 활성화되어 있는지 확인합니다.
2. 팀 메인 메뉴에서 **통합 → 봇 계정**을 열고 **봇 계정 추가**를 클릭합니다.
3. 사용자 이름(멤버가 `@`로 멘션할 이름), 표시 이름, 아이콘을 설정합니다.
4. **봇 계정 만들기**를 클릭하고 표시되는 토큰을 복사합니다. Mattermost는 한 번만 보여줍니다.
5. 봇이 동작할 채널에 봇을 추가합니다. 봇은 자신이 속한 채널의 메시지만 받을 수 있습니다.

<Callout type="warning">
토큰을 이슈, 채팅 메시지, 로그, 소스 저장소에 붙여넣지 마세요. 노출되었다면 **통합 → 봇 계정**에서 폐기하고 새 토큰으로 다시 연결하세요.
</Callout>

<Callout type="info">
개인 액세스 토큰이 아니라 **봇 계정**을 사용하세요. Multica는 개인 토큰을 거부합니다. 봇이 보낸 글이 수신 메시지로 되돌아와 스스로에게 답하게 되기 때문입니다.
</Callout>

## 2. 에이전트에 연결하기

1. Multica에서 **에이전트**를 열고 대상 에이전트를 선택한 뒤 **통합**을 엽니다.
2. **Mattermost 연결**을 클릭합니다.
3. Mattermost 서버 URL(예: `https://mattermost.example.com`)과 봇 액세스 토큰을 붙여넣습니다.
4. **이 봇을 사용할 수 있는 사용자**를 선택합니다.
5. **에이전트에게 보낼 기록**을 선택합니다. **채팅 기록**을 선택했다면 기간도 선택한 뒤 **연결**을 클릭합니다.

Multica는 서버에 요청해 토큰을 검증하고, 해당 계정이 봇인지 확인하고, 토큰을 암호화해 저장한 뒤 관리되는 WebSocket 연결 하나를 엽니다. 이미 다른 에이전트나 워크스페이스에 연결된 봇은 그쪽에서 먼저 연결을 해제해야 합니다.

하나의 워크스페이스에 같은 서버 또는 다른 서버의 봇 여러 개를 연결할 수 있습니다. 토큰, 연결, 컨텍스트 설정, 대화 경로는 에이전트마다 독립적입니다. Mattermost 봇 하나는 에이전트 하나에만 연결할 수 있고, 각 에이전트도 Mattermost 봇 하나만 연결할 수 있습니다.

### 봇을 사용할 수 있는 사용자

- **계정을 연결한 Multica 워크스페이스 멤버**(기본값): 계정 연결, 현재 워크스페이스 멤버십, 에이전트 실행 권한이 필요합니다.
- **지정한 Mattermost 계정**을 선택하면 최대 100개의 `@사용자이름`을 쉼표나 줄바꿈으로 입력할 수 있습니다. 새 계정은 연결된 서버에서 확인하고 계정 ID로 저장하므로 이름이 변경되어도 권한이 다른 사용자에게 넘어가지 않습니다. Multica에 연결된 계정이라도 목록에 없으면 사용할 수 없습니다. 빈 목록은 모두 차단합니다. Multica 계정은 필요 없으며 요청은 봇을 연결한 사용자의 권한, 도구, 연결된 앱을 사용합니다. 계정을 삭제하면 다음 요청부터 차단됩니다.
- **모든 Mattermost 사용자**: Multica 계정이나 계정 연결 없이 DM 또는 봇을 향한 채널 메시지로 요청할 수 있습니다. 요청은 봇을 연결한 사용자를 대신해 실행됩니다. 해당 사용자는 워크스페이스 멤버십과 에이전트 실행 권한을 유지해야 합니다. 이용자는 에이전트의 도구와 연결된 앱을 사용할 수 있으며, 생성된 Multica 채팅은 봇을 연결한 사용자 소유입니다. Multica 계정이나 멤버십은 생성되지 않습니다.

답변은 호출한 DM 또는 원래 채널 스레드에 전달됩니다. 각 DM은 서로 독립적입니다. 접근 모드 변경은 재연결 없이 새 요청에 적용되며, 모드마다 별도의 Multica 대화 기록을 유지합니다. 소유자와 관리자는 연결된 봇 옆의 **수정**에서 변경할 수 있습니다.

**지정한 Mattermost 계정** 모드에서는 **목록에 없는 계정에 대한 응답**을 텍스트 또는 컴퓨터에서 업로드한 이미지 모음 중 무작위로 고른 한 장으로 설정할 수 있습니다. 이미지를 개별적으로 추가하거나 삭제할 수 있으며, 응답마다 독립적으로 선택하므로 같은 이미지가 다시 나올 수 있습니다. 기존 단일 이미지 설정은 한 장짜리 모음으로 유지됩니다. 이미지는 PNG, JPEG, GIF, WebP 형식으로 이미지당 최대 5 MiB, 텍스트는 최대 4000자입니다. 텍스트를 비우면 기본 접근 거부 메시지를 사용합니다. Mattermost로 직접 전송하며 채팅을 만들거나 에이전트를 실행하지 않으므로 에이전트 토큰을 사용하지 않습니다. 이미지는 설명 없이 첨부됩니다. 봇을 향하지 않은 채널 메시지나 중복 수신에는 다시 응답하지 않습니다. 이미지를 읽을 수 없거나 Mattermost가 업로드를 거부하면 기본 텍스트 응답을 보냅니다.

### 컨텍스트 선택

- **현재 메시지만**(기본값): 스레드의 첫 메시지를 포함한 추가 Mattermost 기록을 에이전트에게 보내지 않습니다.
- **전체 스레드**: 요청이 속한 스레드를 해당 요청까지 가져옵니다. 최상위 게시물에는 이전 스레드 메시지가 없습니다.
- **채팅 기록**: 현재 채널이나 DM에서 요청 이전 **1시간, 6시간, 24시간, 3일, 7일, 30일, 60일, 90일, 1년(365일)** 동안의 메시지와 답글을 가져옵니다. **제한 없음**은 날짜 제한만 없애며, 아래의 메시지 수, 크기, 읽기 한도는 그대로 적용됩니다.

요약 봇은 **전체 스레드**를 선택한 뒤 대화에서 `@summary 결정 사항, 할 일, 담당자, 미해결 질문을 요약해 줘`라고 멘션하면 됩니다. 채널의 여러 대화를 요약하려면 **채팅 기록**을 선택합니다. 메시지 URL을 따라 다른 채널을 읽지는 않습니다.

선택한 기록에는 다른 참여자의 메시지도 포함되며, 요청과 함께 Multica에 저장되고 에이전트 모델에 전송됩니다. 기존 Multica 대화 기록과는 별도입니다. `/new`나 `/clear`로 대화 컨텍스트를 초기화해도 다음 요청에서 선택한 Mattermost 기록을 다시 가져올 수 있습니다. 설정을 바꾸려면 에이전트의 통합 탭 또는 **설정 → 메시징 → Mattermost**에서 연결된 봇 옆의 **수정**을 선택하고 저장하세요. 액세스 토큰은 필요 없습니다. 변경 사항은 보통 30초 이내에 자동으로 적용됩니다.

기록에는 텍스트, 작성자, 시간, 게시물 링크와 활성화된 경우 첨부 파일 참조가 포함됩니다. 요청당 최대 1,000개 메시지, 직렬화된 항목 128 KiB, 메시지당 4,000자로 제한되며 페이지 수와 시간에도 제한이 있습니다. 생략된 기록은 부분 기록으로 표시하고 에이전트에게 이를 알리도록 지시합니다. 읽기 실패는 기록 사용 불가로 표시합니다. 파일과 이미지 내용은 자동으로 다운로드하지 않습니다. 기록이 많을수록 모델 컨텍스트 사용량도 늘어납니다.

### 필요할 때 기록 읽기

**현재 메시지만** 설정을 유지하면서 요청에 필요한 기록을 가져올 수 있습니다. 공유 `mattermost-readonly` skill(소스: `deploy/nord/skills/mattermost-readonly`)을 할당하고 에이전트의 비밀 환경 변수에 `MATTERMOST_URL`과 `MATTERMOST_TOKEN`을 설정하세요. 해당 봇의 토큰을 사용해야 합니다. `MULTICA_TOKEN`으로는 Mattermost에 인증할 수 없습니다. 런타임에는 Mattermost 서버 연결과 Python 3가 필요합니다.

첫 실행부터 출처의 `channel_id`, `thread_id`, `post_id`가 실행 컨텍스트에 전달되며 이후 실행마다 갱신됩니다. 그룹의 최상위 메시지는 자체가 스레드 루트이고, 스레드 밖의 DM은 스레드 ID가 비어 있습니다. 이 ID는 에이전트 실행 컨텍스트에 유지됩니다. skill은 필요한 채널이나 스레드를 페이지별로 읽습니다. Multica에 저장된 대화 기록은 전체 Mattermost 채널이 아닙니다.

이 설정은 자동 기록 설정과 별개입니다. 도우미 스크립트는 읽기만 수행하지만 원본 토큰에는 봇 계정의 모든 권한이 유지됩니다. 토큰을 교체하면 에이전트 환경 변수도 갱신해야 합니다. 통합 연결을 해제해도 별도로 설정한 자격 증명은 삭제되지 않습니다.

## 첫 사용과 계정 연결

아래 계정 연결 절차는 **계정을 연결한 Multica 워크스페이스 멤버** 모드에만 적용됩니다.

멤버가 봇에게 처음 메시지를 보내면 봇이 일회용 Multica 계정 연결 링크를 보냅니다. 링크를 열어 같은 Multica 워크스페이스에 로그인하고 표시된 계정 연결을 확인한 뒤 Mattermost로 돌아와 메시지를 다시 보내세요. 링크는 15분 후 만료되며, 봇에게 다시 메시지를 보내면 새 링크를 받습니다.

채널에서는 봇이 이 링크를 공개적으로 게시하지 않고, 먼저 DM을 열어 달라고 안내합니다.

현재 워크스페이스 멤버만 봇을 사용할 수 있으며, 멤버십은 메시지마다 다시 확인합니다.

## 봇 사용하기

### 다이렉트 메시지

봇과 DM을 열고 텍스트를 보내세요. `@` 멘션은 필요 없습니다.

### 채널과 그룹 메시지

봇을 채널에 추가한 뒤 `@`로 멘션하세요. 수락된 메시지는 해당 스레드의 Multica 대화를 이어갑니다. 봇을 향하지 않은 채널 잡담은 수집되지 않습니다.

추가 텍스트 없이 `@multica`만 보내도 설정된 지침과 선택한 컨텍스트로 에이전트를 실행합니다.

스레드의 루트 게시물을 봇이 직접 작성한 경우에는 멘션 없는 답글도 봇에 전달됩니다. 봇이 시작한 대화는 이름을 반복하지 않고 이어갈 수 있습니다. 사람이 만든 스레드에서는 매번 멘션하세요.

각 스레드가 독립된 Multica 채팅입니다. 한 채널의 멘션 스레드 두 개는 서로 독립된 대화이고, DM은 하나의 연속된 대화입니다.

### 명령

예시의 `@multica`를 실제 봇 사용자 이름으로 바꾸세요. DM에서도 멘션을 먼저 입력해야 Mattermost 기본 슬래시 명령 대신 일반 메시지로 전송됩니다.

- `@multica /issue <제목>`은 Multica 이슈를 만듭니다. 다음 줄들은 선택적 설명이 됩니다. 제목 없는 `@multica /issue`는 사용법을 안내합니다.
- `@multica /new`는 비어 있는 Multica 채팅을 새로 만들고 해당 스레드의 이후 메시지를 그쪽으로 보냅니다. `@multica /new <메시지>`는 그 메시지를 첫 턴으로 사용합니다.
- `@multica /clear`는 현재 Multica 채팅을 유지한 채, 다음의 비어 있지 않은 메시지부터 에이전트가 보는 컨텍스트를 새로 시작합니다.

<Callout type="info">
이들은 일반 메시지 본문으로 입력하는 Multica 메시지 명령입니다. Mattermost 슬래시 명령이 아니므로 시스템 콘솔에 등록할 필요가 없습니다.
</Callout>

### 답변과 지원 콘텐츠

봇은 요청이 온 스레드에 답하고, 에이전트의 Markdown을 그대로 렌더링하며, 서버의 최대 게시물 크기에 맞춰 긴 답변을 나눕니다. 답변은 스트리밍이 아니라 에이전트가 끝난 뒤 한 번에 게시됩니다.

봇은 에이전트가 만든 이미지와 파일을 보낼 수 있습니다. 에이전트가 `multica attachment upload <local-path>`를 실행하면 답변 텍스트 뒤에 각 첨부 파일이 같은 스레드의 별도 게시물로 전달됩니다. 첨부 파일만 있는 답변도 지원합니다. Multica 객체 저장소와 Mattermost에서 봇의 `upload_file` 권한이 필요합니다. 파일당 한도는 100 MiB이며, Mattermost 서버의 한도가 더 낮으면 해당 한도가 적용됩니다. 파일을 사용할 수 없거나 업로드가 영구적으로 거부되면 봇이 안내를 게시하고 나머지 파일 전송을 계속합니다.

**에이전트에게 보낼 첨부 파일** 설정은 현재 메시지와 선택한 기록에 적용됩니다.

- **링크 보내기**(기본값): 파일 이름, MIME 유형, 크기, 임시 다운로드 링크를 전달합니다. 파일 내용, 미리보기 이미지, 동영상 프레임은 대화에 넣지 않습니다. 에이전트는 사용자 요청에 필요한 파일만 `multica attachment download '<download_url>' -o ./attachments`로 다운로드하도록 안내받습니다.
- **보내지 않기**: 첨부 파일 참조를 제외합니다. 텍스트는 처리하지만 봇을 향한 파일 전용 메시지에는 지원하지 않는다는 안내를 보냅니다.

요청당 최대 50개 파일 참조를 포함하며 현재 메시지와 최근 기록 순으로 우선합니다. 메타데이터를 읽지 못하면 사용 불가로, 한도를 넘으면 불완전한 목록으로 표시합니다. 링크 모드에서는 파일만 있는 DM도 전달하고 지시가 없으면 무엇을 할지 묻습니다. 봇을 향하지 않은 채널 첨부 파일에는 반응하지 않습니다.

`MULTICA_PUBLIC_URL` 설정과 에이전트 런타임의 Multica CLI 업데이트가 필요합니다. 링크는 파일 하나에 대한 접근을 24시간 허용하므로 공개하지 마세요. 통합 비활성화나 설정 변경, 워크스페이스 이동, 원본 게시물 삭제, 봇 접근 권한 상실 시 기존 링크는 사용할 수 없습니다. 만료 후에는 파일을 다시 공유하거나 해당 파일이 포함된 기록으로 봇을 호출하세요. 수신 링크 모드에는 객체 저장소가 필요 없으며 명시적으로 다운로드하기 전까지 파일은 Mattermost에 남습니다.

입력 중 표시는 없습니다. Mattermost는 이를 WebSocket으로만 제공하며, 이미 처리 중인 메시지에 대해 Multica가 호출할 수 있는 서버 측 수단이 없습니다.

### 전송 복구

실행이 실패하고 예정된 자동 재시도가 없으면 봇이 원래 대화에 짧은 오류 알림을 보냅니다. 내부 오류 상세 정보는 Multica에만 남습니다. 새로 발생한 실패만 알림 대기열에 추가되므로 서버를 업데이트해도 과거 실패 알림은 전송되지 않습니다.

응답과 전송된 부분은 데이터베이스에 기록되며 재시작 후에도 처리가 재개됩니다. 명확한 일시적 거부는 재시도합니다. POST 응답이 유실되면 중복 전송 대신 봇의 전송 마커를 찾습니다. 결과가 불확실하면 확인 대기 상태와 로그를 남기므로 수동 재전송 전에 Mattermost와 Multica 응답을 확인하세요. 확인 범위는 최대 4000개 게시물입니다. WebSocket 연결이 끊긴 동안의 수신 메시지는 다시 가져오지 않습니다.

## 연결 관리

**설정 → 메신저 → Mattermost**에서 연결된 봇과 각 봇이 속한 서버를 확인할 수 있습니다. 소유자와 관리자는 연결을 해제할 수 있습니다. 해제하면 연결이 닫히고 발신도 멈추지만 Multica의 대화와 감사 기록은 유지됩니다.

## 셀프 호스팅 설정

API 서버를 시작하기 전에 안정적인 32바이트 암호화 키를 설정하세요.

운영자는 `MULTICA_MATTERMOST_ALLOWED_SERVERS`에 허용할 정확한 HTTPS 기본 URL을 쉼표로 구분해 설정해야 합니다. 하위 경로도 포함하세요. HTTP, 인증 정보가 포함된 URL, 쿼리, 프래그먼트 및 승인되지 않은 대상은 거부됩니다. URL을 제거하면 기존 연결의 다음 접속과 전송도 차단됩니다.

```dotenv
MULTICA_MATTERMOST_SECRET_KEY=<base64로 인코딩한 32바이트 키>
MULTICA_MATTERMOST_ALLOWED_SERVERS=https://mattermost.example.com
```

`openssl rand -base64 32`로 생성할 수 있습니다. 장기간 보관하세요. 분실하거나 교체하면 저장된 봇 토큰을 해독할 수 없어 봇을 모두 다시 연결해야 합니다.

각 설치는 운영자가 승인한 서버 URL을 사용합니다. 허용 목록에 여러 서버를 지정할 수 있습니다.

연결 링크는 `MULTICA_APP_URL`을 사용하며, 없으면 `FRONTEND_ORIGIN`으로 대체합니다. 생성된 주소는 멤버가 접근할 수 있어야 합니다.

<Callout type="warning">
Multica는 Mattermost 서버와 통신할 때 HTTP 리다이렉트를 절대 따라가지 않으므로, 잘못 설정된 리다이렉트가 봇 토큰을 다른 호스트로 보낼 수 없습니다. 배포에 리다이렉트(예: HTTP → HTTPS)가 있다면 브라우저에서 실제로 사용하는 최종 URL을 입력하세요.
</Callout>

## 문제 해결

- **봇을 검증할 수 없음**: 먼저 서버 URL과 API 서버의 네트워크·프록시 설정을 확인하세요. 토큰 재발급이 필요한 경우는 Mattermost가 직접 거부했을 때뿐이며, 오류 메시지가 두 경우를 구분합니다.
- **"이 토큰은 사용자 계정의 것입니다"**: 개인 액세스 토큰을 붙여넣었습니다. 봇 계정을 만들고 그 토큰을 사용하세요.
- **채널에서 답이 없음**: 봇이 해당 채널의 멤버인지, 메시지가 `@`로 멘션했는지 또는 봇이 시작한 스레드의 답글인지 확인하세요.
- **`@channel`로 봇이 반응하지 않음**: 의도된 동작입니다. 봇은 자기 이름에만 반응하므로 브로드캐스트 멘션으로 채널의 모든 봇이 한꺼번에 호출되지 않습니다.
- **연결 링크 만료**: 봇에게 DM을 다시 보내고 가장 최근 링크를 사용하세요.
- **봇이 실행되지 않음**: 에이전트가 보관 처리되었는지, [런타임](/daemon-runtimes)이 온라인인지 확인하세요.
